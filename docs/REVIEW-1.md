# REVIEW-1: Prompt Piggy blueprint and task packages

Reviewer: fresh critic (opus, max rigor). Reviewed `out/ARCHITECTURE.md` (1,604 lines) and `out/orchestrator-tasks.json` (32 tasks, g0 to g10) against `HARDENING_CONSTRAINTS.md`, `FACTS.md`, `BRIEF.md`, and `~/work/skylite`. Date 2026-10-24.

## Verdict: PASS_WITH_FIXES

The design is unusually careful, and most of the attacked surfaces held. Four HIGH defects must be fixed in the blueprint and task JSON before dispatching PP-06, PP-13, PP-20, PP-22, and PP-23:

- the hardening loop lets a player poison the validator cheaply,
- the two attempt RPCs deadlock against each other,
- a single breach is paid repeatedly until promotion,
- no task owns deploy or staging.

No CRITICAL defect was found.

### What was attacked and held (no finding)

- **Win spoofing through text.** A win requires a `RunToolCallItem` named `approveTransfer` plus the per-run context flag that only the stub's `execute` sets. The tool has strict enum-only parameters, it is the only tool, and parallel tool calls are off. A tool item without the flag is `fail` (§8.4, PP-19). Text that looks like a tool call cannot create a `function_call` item.
- **Double finalize or forged finalize.** `record_attempt` is `service_role`-only, requires `pending`, takes `FOR UPDATE`, and checks outcome invariants (§5.4 L704-707). The attempt id never comes from the client.
- **Nonce or delimiter escape** into the Core LLM and into the Hardening Engine. The payload is JSON-encoded with `<`, `>`, and `&` escaped, inside 128-bit nonce tag names, and the engine is forced into strict structured output whose schema has no free text (§8.3, §8.5, PP-10, PP-20).
- **HC-A1 path audit.** Every route by which text reaches an LLM was enumerated: Core instructions, the Core user message, Decisions `instructions` and `input`, the engine developer and user messages, the stage B breach replay, and stage B refusal scoring. No path carries `block_keywords`. Attacker text reaches models only in the user role (§6.9).
- **Realtime publication.** It is pinned to `treasury` and `live_feed`, both of which have no free-text columns (§5.5, PP-18, PP-28).
- **Other controls that held:**
  - `/live` renders labels only (T18).
  - The `server-only` admin client is guarded by an import guard and a bundle scan.
  - The E2E flag is hard-false in production.
  - `proxy.ts` is limited to session refresh (HC-A4).
- **HC3 reconciliation for cracks** is documented (HC-A5, §9.1) and sound: the crack transition is a pure function of a server-computed enum.

### Claims verified during review

- Next 16 `proxy.ts` defaults to the Node runtime, and a `runtime` export throws (https://nextjs.org/docs/app/api-reference/file-conventions/proxy, "Runtime" and "Version history").
- The Decisions API is `POST /v1/decisions`, accepts only `gpt-6-luna`, takes 1 to 400 questions, uses `choices[{value, description}]`, returns `answers[]` with `probability`, `choice`, `probabilities`, and `confidence`, returns refusals as `type: "refusal"`, has the SDK method `client.decisions.create()`, needs a 1,024-token prefix for caching, and costs $0.10 per 1M uncached input tokens (https://developers.openai.com/api/docs/guides/decisions).
- In the Agents SDK, `runInParallel: true` is the default. Input guardrails run on the first agent only. Output guardrails also run when a tool result becomes the final output, and they receive `details` with `modelResponse` and the turn's items. This resolves the ARCH §8.8 UNVERIFIED item about output guardrails after `stop_on_first_tool` (https://raw.githubusercontent.com/openai/openai-agents-js/main/docs/src/content/docs/guides/guardrails.mdx).
- On npm, `@openai/agents@0.21.0` depends on `openai ^7.2.0` and has the peer dependency `zod ^4.0.0`. `openai@7.43.0` exists and has the peer `zod ^3.25 || ^4.0`. `next` latest is 16.4.3.
- Strict structured outputs support `minLength`, `maxLength`, `pattern`, `minItems`, and `maxItems` (OpenAI community changelog "Structured Outputs gets nifty improvements"; the official supported-schemas anchor did not render).
- Skylite matches the claims in ARCH §1.2 rows 3, 4, 6, 14, and 19 (checked at `admin.ts:1-90`, `middleware.ts:41-56`, `auth/callback/route.ts:7-13`, `cron/calendar-sync/route.ts:12-29`, and `vitest.config.ts:20,52`).
